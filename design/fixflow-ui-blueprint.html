02 · Team split
Phân công 3 màn hình cốt lõi cho từng thành viên
SV1 · Người yêu cầu

Luồng tạo & theo dõi ticket

Cốt lõi 1: Ticket Create — nhập thiết bị, vị trí, mô tả, ảnh, mức độ.

Cốt lõi 2: My Tickets — danh sách, tìm kiếm, lọc theo trạng thái/SLA.

Cốt lõi 3: Ticket Detail — timeline, trao đổi, hủy/đóng và đánh giá.

Lát cắt end-to-end: HTML form → validation → mock JSON/LocalStorage → responsive → commit → OBS.

SV2 · Kỹ thuật viên

Luồng nhận & xử lý sửa chữa

Cốt lõi 1: Work Queue — nhận việc, ưu tiên, lọc theo kỹ năng/SLA.

Cốt lõi 2: Repair Detail — cập nhật trạng thái, ghi chú, vật tư, checklist AI.

Cốt lõi 3: Repair History — lịch sử sửa, bằng chứng và lỗi lặp.

Lát cắt end-to-end: DOM events → checklist AI → trạng thái loading/error → dữ liệu giả lập → review SV1.

SV3 · Điều phối & quản trị

Luồng quyết định & quản lý dữ liệu

Cốt lõi 1: Dispatch Board — kéo/thả hoặc gán kỹ thuật viên cho ticket.

Cốt lõi 2: SLA Monitor — KPI, cảnh báo quá hạn, bộ lọc và drill-down.

Cốt lõi 3: Asset Management — CRUD thiết bị, lịch sử và trạng thái tài sản.

Lát cắt end-to-end: dashboard → CRUD → responsive → tích hợp navigation → phát hành/QA.

AI-1 · Ticket Classifier
Input: mô tả lỗi + thiết bị. Output: nhóm kỹ thuật, ưu tiên, lý do. Tác động: gợi ý assignee.
AI-2 · Repair Checklist
Input: loại lỗi + thiết bị. Output: checklist. Tác động: kỹ thuật viên thực hiện và lưu kết quả.
AI-3 · Failure Pattern
Input: lịch sử ticket. Output: tóm tắt lỗi lặp, độ chắc chắn. Tác động: quyết định bảo trì.
Fallback bắt buộc: “Không đủ dữ liệu để đưa ra đề xuất.” / “AI chưa chắc chắn về kết quả này.” Có nút Thử lại · Chỉnh sửa · Dùng thủ công · Báo cáo.

□ accessibility cơ bản
□ branch + PR + review
□ video OBS + README cập nhật
Thứ tự triển khai đề xuất
  1. Chốt design tokens, sidebar, button, table, status badge.

  4. Test responsive, lỗi/rỗng/loading, review chéo và quay OBS.
